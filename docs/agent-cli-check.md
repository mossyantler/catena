# Agent CLI 보조 확인 결과 (T08)

명세 13장 「사용자 시험」의 보조 확인(통과 조건 아님)이다. 진행 방식은 `docs/user-test.md` 8절을 따랐다. Coding Agent에게 CLI의 JSON 출력만 쓰게 하고, 사용자 시험과 같은 과제(Q1~Q6, Q8)를 풀게 했다. Agent-invoked 질의가 쓸 만한지 보는 것이 목적이다.

- 날짜: 2026-11-13
- 대상: `simulated` 묶음 두 개. `roombook-sim-1`과 `expense-sim-1`이고, 둘 다 재생 위치 201 / 201이다.
- 참가 Agent: 시나리오마다 하나씩, 이 저장소의 대화 맥락을 모르는 별도 Agent(Claude Code의 하위 Agent)를 썼다.
- Agent에게 준 것: 과제 문장과 CLI 명령 목록(`docs/user-test.md` 8절의 표)만 줬다. 정답은 주지 않았다.
- 규칙: `node tools/catena.ts <명령> --bundle scenarios/<이름> --json`만 실행한다. 파일 읽기, 목록 보기, 다른 명령은 쓰지 않는다.
- 규칙을 지켰는지는 각 Agent가 보고한 실행 명령 목록으로 확인했다. 실제 도구 호출 기록을 직접 대조하지는 않았다.
  - roombook: CLI 호출 17번.
  - expense: CLI 호출 15번. 셸 구문(`cd &&`, `echo`, `for`)으로 CLI를 감싸 부른 적은 있지만, 파일 읽기나 목록 보기는 없었다.
- 채점: `docs/user-test.md` 4절의 정답과 판정 기준에 따랐다.

## 2. JSON 형식 개선 후보

틀린 과제가 없어서 "틀린 과제를 JSON 수정의 입력으로 쓴다"는 해당이 없다. 그 대신 두 Agent가 "부족했던 점"으로 보고한 것을 모았다. 같은 지적이 두 시나리오에서 함께 나오면 공통으로 적었다.

| # | 지적 | 나온 과제 | 공통 | 후보 |
|---|---|---|---|---|
| 1 | 승인이 어느 조건·슬롯을 처리하는지 연결이 없다(A02-2, A05-2가 무엇을 인수하는지, 먼저 처리된 A0x-1은 무엇이었는지) | Q2, Q5 | 둘 다 | `inbox`와 승인 항목에 `condition_ids`와 슬롯을 싣는다 |
| 2 | 원문(검사 로그, diff, transcript)이 해시 참조로만 나와 내용을 볼 수 없다. 왜 실패했는지 CLI로 알 수 없다 | Q4, Q5, Q6 | 둘 다 | 원문 보기 명령(`raw <ref>`)을 더한다. 화면에는 이미 원문 보기가 있다 |
| 3 | 직·간접 후행과 독립 Task를 바로 주는 질의가 없어 `task_edges`를 손으로 따라가야 했다 | Q3 | 둘 다 | `show <Task>`에 선행·후행·독립(읽기 모델 `relations`, 화면의 전체 의존 선택과 같은 값)을 싣는다 |
| 4 | "시도"가 `attempt`(Run)와 `round`(수정 회차) 두 단위라 질문의 뜻이 애매하다 | Q8 | 둘 다 | 필드 이름이나 설명을 분명히 한다(예: `run_attempt`, `repair_round`) |
| 5 | 사람 승인을 기다리는데도 대표 상태(`rep`)는 "실행 중"이다. `stages`와 `waits`를 함께 봐야 안다 | Q1 | 둘 다 | 카드 JSON에 "지금 기다리는 것" 요약을 싣는다. 대표 상태 규칙(명세 Task 상태)은 그대로 둔다 |
| 6 | 인수된 Task도 `rework: true`가 남아 "지금 문제인 Task"와 "예전에 반복이 있었던 Task"를 구분할 수 없다 | Q8 | roombook | `rework`를 지금 진행 중인 반복과 지난 반복으로 나눈다 |
| 7 | `decision` 대기의 선택지(새 시도, 중단 등)가 나열돼 있지 않다 | Q5 | roombook | 대기 사유가 허용 응답을 싣는다(`dashboard_interaction_design.md` I10) |
| 8 | 닫힌 Task(roombook T13 취소)가 `status`에서 아무 표시 없이 빠진다 | Q1 | roombook | 닫힌 Task 수나 목록을 따로 싣는다 |
| 9 | JSON에 "지금" 시점(마지막 이벤트 시각)이 없어 마지막 보고 뒤 얼마나 지났는지 모른다 | Q4 | expense | `source`에 재생 위치의 시각을 싣는다 |
| 10 | `cost_usd: 0`이 정산 전인지 실제 0인지 구분되지 않는다 | Q4 | expense | 정산 전이면 비우거나 신뢰도를 함께 싣는다(5-7) |

- 1~4는 두 시나리오에서 함께 나왔고, 과제에 답하는 데 드는 조회 수나 추론을 직접 늘렸다. 먼저 고칠 후보다.
- 5는 화면 카드에서도 같은 질문이 생길 수 있다. 사용자 시험(T06)의 결과와 함께 보는 것이 좋다.

## 3. 해석과 한계

- **Agent-invoked 질의는 쓸 만하다.** 두 Agent 모두 화면 없이 CLI JSON만으로 7개 과제를 모두 맞혔다. 각각 CLI를 15~17번 불렀고, 한 번에 100초 안팎이 걸렸다.
- **사람 사용자의 이해도와는 다르다.** 이것은 통과 조건이 아니며, 사람이 화면을 이해하는지는 사용자 시험(T06)이 잰다. Agent는 JSON 전체를 끝까지 읽기 때문에, 사람이 화면에서 놓치는 것을 놓치지 않을 수 있다.
- **같은 계열 모델이다.** 참가 Agent는 이 시안을 만든 Agent와 같은 계열의 모델이라, 용어와 구조를 해석하는 습관이 비슷할 수 있다. 다른 Coding Agent(Codex 등)로 해 보는 것은 하지 않았다.
- **한 번씩만 했다.** 시나리오마다 한 번씩 한 결과라 우연히 맞았을 가능성을 배제할 수 없다.
